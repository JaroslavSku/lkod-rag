## O projektu LKOD
LKOD (Lokální katalog otevřených dat) je open-source řešení pro publikaci otevřených dat veřejných institucí, je součástí projektu Golemio a vyvíjí ho společnost Operátor ICT, a.s. (operatorict.cz); řeší povinnost veřejných institucí publikovat otevřená data tím, že poskytuje přehlednou správu datových sad, veřejně dostupný katalog a automatickou synchronizaci s NKOD (Národní katalog otevřených dat); kontakt pro nasazení formou služby LKOD as a Service je lkod@operatorict.cz nebo telefon +420 770 380 067, obecný kontakt Golemio je golemio@operatorict.cz.
## Repozitáře a komponenty LKOD
LKOD je rozdělen na dvě hlavní komponenty: lkod-catalog-2-0, veřejná katalogová frontendová aplikace, kterou vidí koncoví uživatelé a vyhledávají v ní datové sady, a lkod-admin-backend-2-0, administrační backend, kde si vydavatelé (organizace) datové sady zakládají, upravují a publikují a který poskytuje autentizovaná i veřejná (/public/*) REST rozhraní; katalogová frontend aplikace komunikuje s administračním backendem výhradně přes veřejné, needentifikované endpointy GET /public/datasets, GET /public/datasets/:id, GET /public/organizations a GET /public/themes, přičemž většina z nich vyžaduje HTTP hlavičku x-tenant-id identifikující nadřazenou organizaci (tzv. founder), výjimkou je /public/themes, které je globální a hlavičku nepotřebuje; architektura systému je víceuživatelská (multi-tenant) a data jednotlivých institucí jsou v administračním backendu izolována pomocí Row-Level Security (RLS) v PostgreSQL na základě founder_id.
## Technologický stack katalogu
Katalogová frontend aplikace (lkod-catalog-2-0) je postavena na Next.js (App Router) s TypeScript ve striktním režimu, běží na React 19, celá aplikace je v režimu dynamic = "force-dynamic" (statická generace je vypnutá), formuláře řeší Formik s Yup validací, perzistenci filtrů v URL zajišťuje knihovna nuqs, logování běží přes Pino s úrovní nastavitelnou proměnnou LOG_LEVEL, stylování je SCSS moduly per komponenta kontrolované Stylelintem, testování zajišťuje Jest s Testing Library (jsdom), e-mailové notifikace z kontaktního formuláře běží přes Nodemailer, a správa stavu je řešena bez Reduxu či Zustandu, pouze pomocí React Contextu a vlastních hooků.
## Datová vrstva a napojení na zdroje dat
Katalog podporuje dva zdroje dat, mezi kterými se přepíná proměnnou prostředí DATA_SOURCE: json-service.ts čerpá data z REST/JSON API administračního backendu, sparql-service.ts čerpá data přímo dotazy na SPARQL endpoint, catalog-service.ts funguje jako továrna, která na základě konfigurace vybere aktivní službu, a cached-service.ts obaluje operace katalogu React funkcí cache(), aby se v rámci jednoho serverového renderu nevolala stejná data opakovaně; sdílené promise hodnoty pro vydavatele, témata, klíčová slova a formáty poskytují React Context providery DataProvider a OrganizationsProvider, ke kterým komponenty přistupují přes hooky jako usePublishersPromise() a čekají na výsledek pomocí Suspense.
## Routing a stránky
Katalog používá Next.js App Router s klíčovými cestami /datasets/[slug] pro detail datové sady a /organizations/[organization] pro detail vydavatele; next.config.js definuje trvalá přesměrování, například ze staré cesty /about na /project a z /group/:path* na hlavní stránku; aplikace navíc nabízí explorativní analýzu datových sad se statistikami, vizualizacemi rozložení dat, korelacemi proměnných a identifikací chybějících či odlehlých hodnot u konkrétní datové sady.
## Bezpečnost
Bezpečnostní politiku prosazuje middleware v src/proxy.ts pomocí Content-Security-Policy (CSP) s nonces a bez unsafe-eval v produkci, povoluje jen vybrané externí služby (Plausible Analytics, Microsoft Clarity, Google Analytics, Cloudflare) a vynucuje striktní CORS, HSTS a X-Frame-Options; webová analytika Plausible neukládá osobní ani identifikovatelné údaje, nepoužívá trvalé identifikátory ani cookies a veškerá měření jsou anonymní a agregovaná; kontaktní formulář (src/actions/sendEmail.ts) používá sanitizeInput() a maskování e-mailových adres v logách kvůli ochraně osobních údajů.
## Konfigurace a feature flags
Veškerá konfigurace katalogu se načítá z proměnných prostředí přes src/config.ts, kompletní přehled je v souboru .env.template; mezi konfigurovatelné prvky patří ENDPOINT, ICONS_URL, PUBLIC_URL a ADMIN_URL pro adresy backendu, CTA_BANNER_ENABLED jako feature flag pro banner "LKOD jako služba", NOTIFICATION_BANNER_TEXT a NOTIFICATION_BANNER_SEVERITY pro konfigurovatelné upozornění (info/warning/error), MAILER_ENABLED a související MAILER_* proměnné pro SMTP nastavení kontaktního formuláře, SITEMAP_TENANT_SLUGS pro seznam tenantů v sitemap.xml a REVALIDATE_SECRET jako token pro on-demand revalidaci cache.
## Lokalizace
Katalog je v současnosti pouze v češtině, všechny textové řetězce uživatelského rozhraní jsou uloženy v souboru src/textContent/cs.json a vícejazyčný (i18n) framework zatím není zaveden.
## Legislativní a datový rámec
Publikace otevřených dat veřejnými institucemi je v ČR zákonná povinnost a LKOD pomáhá organizacím tuto povinnost splnit tak, aby byla data přehledně evidovaná a udržovaná v souladu s legislativou, automaticky synchronizovaná s NKOD (Národní katalog otevřených dat) a veřejně dostupná v podobě strojově čitelného katalogu; přístupnost webu lkod.cz je řešena v souladu se zákonem č. 99/2019 Sb., o přístupnosti internetových stránek a mobilních aplikací.
## Testování a CI/CD
Testy běží pomocí Jest a Testing Library v prostředí jsdom, testovací soubory jsou ve složce src/__tests__/, a continuous integration prochází v pořadí lint, npm audit --audit-level=high, build a test (s pokrytím kódu); pro lokální vývoj slouží příkazy npm run dev pro vývojový server na portu 3000 s Turbopackem, npm run build a npm start pro produkční build a spuštění, npm run lint, npm run ts-lint a npm run style:check pro statické kontroly kódu, a npm test s npm run test:watch pro testy.
